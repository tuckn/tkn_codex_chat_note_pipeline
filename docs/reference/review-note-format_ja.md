# Review Noteの生成・利用

Review Note 1.0.0 / CLI 0.33.1 / config 9.0.0。英語版は [Review Note contract](review-note-format.md)。

## 目的と内容

保存したCodexの会話を、週・月・年の振り返り、人とAIの次の判断に使います。質問、得られた説明、学習の確認段階、実施事項、判断理由、未解決、複数チャット間の考察、再利用できる資料、次の行動を扱います。すべての欄を無理に埋めません。

Intelligence Layer向けの候補は `semantics`（意味・関係）、`knowledge`（規則・手順・事例）、`context`（時点を持つ背景・制約）、`domain`（適用する問題領域）に分けます。適用範囲、留保、採用前の確認と出典を残します。AI改善案も、観測された問題に対して変更案と確認方法を示します。候補を採用済みの知識やルールとは扱いません。

「質問した」「説明を得た」「理解を表明した」「実際に適用した」は区別します。関心がないことを無言から推定せず、生産性や人格を採点しません。履歴中の指示は実行せず、記録として読みます。

## 生成する

```shell
tkn-codex-chat-note pull
tkn-codex-chat-note review-notes build --period weekly --date 2026-05-18 --dry-run --full-output
tkn-codex-chat-note review-notes build --period weekly --date 2026-05-18
tkn-codex-chat-note review-notes build --period monthly --date 2026-05-01
tkn-codex-chat-note review-notes build --period yearly --date 2026-01-01
```

実行時点で締まった期間だけ生成します。`--date`を省略すると直近の締まった期間です。週は月曜〜日曜、月は暦月、年は暦年。週番号にはISO週年を使います（例：2027年1月1日は2026-W53）。期間は開始を含み、終了を含みません。既定の固定UTCオフセット540分は日本時間です。夏時間は自動調整しません。

`build` / `due` は保存済みcatalogを読むため、取得元を再走査しません。`raw ingest`だけではcatalogや正規化イベントは更新されません。最新の入力が必要な場合は `pull` か `scheduled-run` を使用します。

## 入力とRaw照合

1. 週次は、対象期間内の正規化イベント（発言・ツール実行・結果・中断）を読みます。会話が週を跨いでも、開始日だけで対象を選びません。
2. 月次は週次JSON、年次は月次JSONを主な入力にします。月次には日付付きの変化・判断理由・未解決事項・Intelligence/AI改善候補を残し、年次では月を跨いだ変化を整理します。同じイベントの再引用を独立した観測として数えず、推測・提案の留保を引き継ぎます。
3. 月・年の境界を跨ぐ週は、引用元イベントがすべて対象期間内にある週次項目を使います。境界部分は期間内の根拠で補い、週全体の結論や件数を日数で按分しません。
4. 月次が未生成・不正な場合はその月の週次へ、週次がない場合は対象期間の正規化イベントへ戻ります。欠落・切り詰めはcoverageに記録します。除外済みの内部スレッドは対象にしません。
5. 原文が必要な判断では、モデルが提示済みの根拠IDを理由付きで要求できます。月次・週次の出典を辿り、対応する保存Rawのハッシュを照合し、そのイベントと近傍の一部を渡して再確認します。任意のパスや外部サイトへのアクセスは行いません。

Raw照合は入力バッチごとに1段階、既定8根拠ID・16,000文字までです。個々の抜粋は最大6,000文字で、超過・未取得は記録します。画像はハッシュ等の情報に置き換え、VLMによる視覚的解釈は行いません。回数・原因・所要時間を確認できなければ、不明・推測のまま残します。

## 保存されるもの

```text
sources.<id>.data_root/reviews/
  weekly/2026/2026-W21.md
  weekly/2026/2026-W21.json
  monthly/2026/2026-05.md
  monthly/2026/2026-05.json
  yearly/2026/2026.md
  yearly/2026/2026.json
sources.<id>.state_root/reviews/
  index.json
  reports/<run-id>.json
  usage/<run-id>/<usage-id>.json
  transactions/<id>.json
  backups/<id>/<previous-output>
cache_root/reviews/<extraction-signature>/<stage-signature>.json
```

各sourceのdata_root/reviewsとstate_root/reviewsに保存します。レビュー設定は `sources.<id>.reviews` に置き、sourceごとに独立して生成します。フォルダ名だけでIntelligenceとして採用されたことにはなりません。Raw・取得元とは重ねません。

Markdownは人向けの表示、JSONは機械利用の正本です。Markdownへの注記をJSONへ自動反映しません。月次は週次JSON、年次は月次JSONを使います。人が見直した内容を機械利用に反映する場合は、JSONの項目・出典・候補の整合性も確認してください。

JSONの主要フィールドは次のとおりです。

| フィールド | 意味 |
|---|---|
| schemaVersion / id / period | 契約版、同じ保存先・暦期間で維持するID、期間・UTCオフセット |
| items | category、title、text、basis、evidenceIds、caveat、nextCheck、intelligenceKind |
| evidence | 根拠の本文・日時・正規化/Rawへの参照とハッシュ。週次・月次由来の項目はsupportsで元根拠へ辿る |
| sourceInventory / coverage | 読んだ資料、weeklyInputs・monthlyInputs、catalogの観測時点、不足・切り詰め。completeHistoryは常にfalse |
| intelligenceCandidates / aiImprovements | 該当itemsの再利用用一覧。ID・status=candidateを追加。自動採用しない |
| generation / inputFingerprint | 生成プロファイル、モデル、条件のhashと期間内入力のfingerprint |

`basis` は `observed`（記録で確認）、`reported`（発言・報告）、`inferred`（推測）、`proposed`（提案）です。参照IDが存在することは、その根拠が主張を意味的に支持することの保証ではありません。元の会話でAIが報告した成功も、実環境で再検証した結果とは区別します。

```shell
tkn-codex-chat-note review-notes validate "C:\path\to\reviews\weekly\2026\2026-W21.json"
```

検証はJSON構造、期間、引用IDと推移的参照を確認します。原資料全体の真正性・意味的正しさを監査するものではありません。モデルの項目契約は [output.schema.json](../../src/tkn_codex_chat_note/profiles/default-jp/output.schema.json)、生成指針は [prompt.md](../../src/tkn_codex_chat_note/profiles/default-jp/prompt.md) です。

## Frontmatterと日英プロファイル

Markdown Frontmatterは **type: chatReview / schemaVersion: "3.0.0"** です。
正本JSONは引き続き内部データ契約 **type: reviewNote / schemaVersion: "1.0.0"** を使います。
週次・月次・年次は `periodKind` で区別します。chatReviewは出典に帰属するチャットの横断的な振り返りであり、
質問・判断・結果・仮説・候補をIntelligence Layerの材料として扱います。採用済みの知識やpermanentノートという分類ではありません。

| プロパティ | 意味 |
|---|---|
| type / title / description | chatReview、期間のタイトル、校正済み概要と留保を空白で連結した説明。概要がなければ空文字 |
| periodKind / periodKey / periodStart / periodEndExclusive / utcOffsetMinutes | 暦期間。終了日は含まない。UTCオフセットだけは整数 |
| sourceApplication / sourceId / source | チャットの取得元アプリ（Codex）、PC等のsource ID、同名の正本JSONへのfile URI |
| coverageStatus / reviewStatus | 入力の不足と、人の確認状態。部分的な記録を完全な履歴とは扱わない |
| generator / generationProfile / provider / requestedModel | CLI名と保存済みの生成設定。CodexのチャットをClaudeで要約する場合もsourceApplicationはCodex。requestedModelは応答モデルの確定情報ではない |
| generatedAt | 今回の内容生成を行った日時。表示だけの更新では保持。内容が同じでも明示的な再生成では新しい値になり得る |
| sourceFingerprint / generationSettingsSha256 | 保存済みの入力・生成条件の識別値 |
| noteProfile / templateVersion / templateSha256 | 表示に使った日英プロファイル、テンプレート版、profile.json・YAML・Markdownテンプレートの内容をまとめたSHA-256 |
| created / updated / noteId | **末尾3項目**。初回作成日時、内容更新日時、正本JSONのidを引き継ぐ安定したID |

新規ノートのcreated・updatedは初回内容生成日時で初期化し、createdは再生成でも保持します。
updatedは項目・根拠・期間・coverage・sourceInventoryが変わる内容更新で更新し、
同じ内容の再生成、引用符や表示テンプレートだけの変更では保持します。
日時を記録していなかった旧JSONではcreatedを未設定（`created:`）とし、updatedは保存済みgeneratedAtを使います。
初回日時を現在時刻やファイルのOS作成時刻で推測しません。以後の再生成でも不明なcreatedは未設定のまま保持します。
JSONは新規生成時からcreated・updatedを任意の追加メタデータとして保存します。旧JSONも引き続き読み込めます。

日時・日付・バージョンはダブルクォートで囲み、時差・小数秒の字面を保持します。
Windowsパスはシングルクォート、file URIは通常の文字列です。英語コメントで項目をグループ化します。
単一値の未設定はコロンのみ、空のdescriptionは `""` です。詳細な出典一覧と校正履歴はJSONに保持します。

ノートの資源は `src/tkn_codex_chat_note/profiles/default-jp/` と `default-en/` にあります。
設定の `sources.<id>.reviews.language: ja` / `en` が自動で選択します。

| ファイル | 用途 |
|---|---|
| profile.json | 出力言語、週・月・年のタイトル |
| frontmatter.template.yaml | Frontmatterの項目順・分類値・コメント。動的な値の引用符はPythonで処理 |
| template.md | Markdown全体の見出し・注意文・表・考察・出典を組み立てるJinja2テンプレート |
| prompt.md | 抽出・原文照合 |
| synthesis-prompt.md | 最終統合 |
| quality-prompt.md | 欠落・根拠・概要の校正 |
| request.template.md | 段階・言語・期間・入力JSONを含むリクエストの枠 |
| repair-prompt.md / audit-repair-prompt.md | モデル出力／校正出力の修復指示 |
| instructions.json | 原文の最終照合、概要、行分割の補助指示 |
| output.schema.json | モデルの項目契約。PydanticのReviewDraftと一致することを起動時に検証 |

[日本語Markdownテンプレート](../../src/tkn_codex_chat_note/profiles/default-jp/template.md)と
[英語Markdownテンプレート](../../src/tkn_codex_chat_note/profiles/default-en/template.md)を独立して変更できます。
生成・校正の方針は実績のある英語の指示文を両方に保持し、リクエストのLanguageで出力言語を指定します。
日英の本文・タイトルはそれぞれのテンプレートで定義します。
プロファイルはパッケージに同梱する資源です。変更をインストール済みCLIへ反映するには `uv tool install . --reinstall` を使います。
`generation.profiles` はBridgeの実行設定であり、このノート用profilesとは別です。

入力・生成条件が同じで表示資源だけが古い場合、通常のreview-notes／scheduled-runで保存済みJSONから更新します。
結果は `rendered`（集計は `renderedCount`）、モデル呼出しは0回です。dry-runは `planned` と理由を返すだけです。
旧出力をバックアップし、編集済み・確認済みノートは保持します。JSON・日時を表示変更に合わせて書き換えません。
プロンプト・リクエスト枠・補助指示の変更は生成の更新対象です。変更したリクエストのcacheを流用しません。
今回は生成方針とリクエストの内容を保って移動し、配置変更による再推論を避けています。

## 定期実行と再開

Windows Task Schedulerから毎日 `scheduled-run` を実行します。Rawを毎回保存・正規化し、締まった期間のレビューを生成します。取得・正規化は推論を行いません。週次は月曜以降、月次は翌月1日以降、年次は翌年1月1日以降の最初の実行が対象です。

`due` 初回の実行日、または設定した `sources.<id>.reviews.start_date` を含む暦期間から始めます。開始日が月・年の途中でも、その月・年のレビューには保存済みの期間全体を使います。開始日以前の締まった期間は自動で全件生成しません。設定変更で開始日を過去にするとバックフィル対象が増えます。

`sources.<id>.reviews.max_calls` はsourceごとのレビュー1実行の上限（既定12回）です。検証済みの分割・Raw照合・統合結果はcacheへ保存し、上限や中断後の次回に再利用します。エラーを無制限に再試行しません。APIプロファイルのトークン・費用上限は従来どおり適用します。複数sourceの回数・実行時間上限はsourceごとに適用します。利用量記録は `build-report` に含まれ、取得できなかったトークン数を0とは扱いません。

入力の変更がない期間は再推論しません。会話に翌週の発言が追加されただけなら、過去週の生成はやり直しません。月次・年次も、選択された下位期間の項目の意味内容・根拠が同じなら再利用します。

`--dry-run` は推論・ネットワーク・ディレクトリ作成・state・cache・ロック・レポート保存を行いません。`--force` は再生成しますが編集保護を解除しません。未確認の編集済み出力を置き換える場合だけ `--allow-edited` を併用し、置換前の内容をバックアップします。reviewStatusがunreviewed以外の出力は保護します。

同じ入力に対する人の編集はそのまま保持します。入力が変わった保護対象はblockedとして報告し、他の期間は処理できます。2ファイルの保存途中で停止した場合は記録済みtransactionから復旧します。復旧前に人がさらに編集した場合は停止して保護します。取得元全体の同時更新については、ハッシュ一致を確認できない資料を不足情報として扱います。

終了コード0は処理完了、1は失敗・保護で処理できなかった項目あり、2は時間・回数等の上限による未完了です。不足を明示したレビューの生成成功は、履歴全体が完全であることを意味しません。

## ツール入力の準備（0.31）

対象期間の会話本文を保持し、通常のツール本文を会話別の索引に置き換えます。
終了コードや診断文字列に問題の兆候がある場合は短い抜粋を残します。引用された
コードにも診断文字列が含まれ得るため、自動的に失敗とは断定しません。索引の
件数はログ件数であり、独立した実行回数・VLM回数ではありません。出典と元の
正規化データ・Rawは保持し、重要な結果や原因は必要に応じて照合します。
モデル入力は最初・最後の観測時刻を示し、出力JSONは全出典時刻を保持します。
会話が1回の入力に収まる場合は途中で分割せず、正規化に失敗した会話は不足情報に
記録して除外します。sourceInventoryに圧縮方針・件数を記録します。既定の回数上限は維持します。

出力契約に反する応答は、元資料を再送せず、応答と検証エラーだけで1回の修復を試みます。
修復にも通常の呼出し・時間上限を適用します。未検証応答は別のチェックポイントに保存し、
検証を通過するまでは正式なレビューノートとして公開しません。

## 読むための最終統合（0.32）

週次・月次・年次で同じ編集方針を使います。抽出段階は根拠付きの項目を保持し、
中間統合は重複と訂正を整理します。最後のcompose段階で、概要、質問・学び、
テーマ別の実施・判断・残る点、文章による横断的考察、AI改善案、Intelligence候補へ編集します。
小さな個人的な質問も、主要な開発作業に埋もれないよう残します。
月次は週ごとの変化、年次は月ごとの変化をまとめ、下位レビューの連結にはしません。

Markdownでは共通の留保を冒頭にまとめ、個別の判断に影響する留保を表や考察に残します。
出典番号は文書単位です。全文抜粋、各項目の根拠ID、日時、basis、候補状態はJSONに保持します。
出典番号は表示時に割り当てるため、版を跨ぐ追跡にはJSONの根拠IDを使います。

最終統合も呼出し・時間上限とcacheの対象です。単一バッチでも抽出後に最終統合を1回行います。
空の期間は推論しません。編集指示だけの変更では、モデル・抽出条件・入力が同じなら抽出cacheを再利用します。
モデルや抽出条件が変わると通常の自動cache再利用はしません。
生成方針の変更は入力fingerprintに反映され、再生成は既存の編集・確認済みノート保護に従います。
統合指針は [synthesis-prompt.md](../../src/tkn_codex_chat_note/profiles/default-jp/synthesis-prompt.md) です。

## 自動校正（0.33）

週次・月次・年次とも、最終統合の後、保存前に校正します。まず、概観・考察以外の本文項目と構造・全フィールドが完全一致するものを除き、元の抽出項目を照合し、既に含まれる・重要なので復元する・理由を付けて省略する、のいずれかに分類します。引用が重なっていても意味は照合します。ただし、モデルによる判定であり、すべての省略を検出する保証ではありません。途中経過をすべて戻さず、結論・再利用の前提・独立した重要な話題を優先します。

次に、本文項目と復元候補を、その引用・近傍発言・同じテーマへ対応付けた抽出項目の原文で確認します。「既に含まれる」とされた項目の原文も渡し、後続訂正や完了報告を保持します。依頼・提案・完了報告、実装と採用、過去と現在、今回のレビューと元会話の画像確認範囲を区別し、必要なら修正・分割・省略します。説明文の発見・再利用目的や、作業場所の現行ルールを確認する改善案も対象です。概要は最後に校正済み本文とその引用から照合し、本文は変更しません。古い概要だけにある事実を加えず、依頼・報告・推測の区別を保ち、完了・保留状態を本文と揃えてからMarkdownを描画します。

進捗報告だけで判断しないよう、次のユーザー発言までの最後の回答、その次のユーザー発言、
引用した会話の保存済み最終回答も候補に含めます。完了・訂正の見落としを減らしますが、
全文の矛盾を網羅的に検索するものではありません。

根拠抜粋は通常1件2,400文字、入力上限に応じて600または300文字へ縮小します。引用と直接の出典を優先し、補助的な近傍発言の省略や途中抜粋を記録します。共有する根拠はバッチ内で一度だけ送ります。抜粋にないことを不在の証拠にせず、残る不確実性を本文に残します。追加の画像認識や任意パスへのアクセスは行いません。

未確認項目、重複判定、不正な統合先、当該項目に提示していない引用、項目形式の不備、復元候補の黙示的な無視は検証で止めます。修復は根拠付きで最大1回、入力・回数・時間上限の対象です。校正未完了の結果は既存ノートを置換しません。上限到達時は確認済みcacheから再開します。空期間はモデルを呼びません。校正方針・schema・版は最終生成の識別に含め、変更していない抽出cacheは再利用します。

JSONの `generation.qualityAudit` に確認方法・件数・抜粋の限界・各判断を保存します。意味の正しさの保証ではありません。`review-notes validate` は従来どおりローカルの構造検証で、モデルを呼びません。この項目のない旧ノートも読めます。

空でないレビューには根拠校正が最低1回増え、完全一致しない抽出項目があれば欠落照合が増え、概要があれば本文との照合が概要1件につき1回増えます。回数は最終案と根拠量に依存するため、dry-runの初期バッチ数だけでは確定しません。取得できた失敗・修復を含む利用量を記録します。本文以外のモデル実行環境の入力、推論・出力も消費するため、復元候補が多いと費用は大きく増えます。`max_calls` により複数回の定期実行にまたがる場合もあります。
[校正プロンプト](../../src/tkn_codex_chat_note/profiles/default-jp/quality-prompt.md)を参照してください。

## 簡潔さの検証（0.34）

統合時は最大32項目・日本語7,000文字（英語20,000文字）、校正後は最大36項目・
8,400文字（英語24,000文字）を検証します。タイトル・本文・留保・確認案の合計で、
引用リンクやMarkdownの構文は含めません。上限を埋める必要はありません。
週次・月次・年次とも主要テーマを選び、優先度の低い実装詳細は保存済み抽出結果に残します。
重要な欠落の復元はレビュー全体で6件まで、そのうち新しい話題は2件までです。
照合候補は qualityAudit.consideredFindings、採否理由は coverageDecisions に保持します。
この照合は全抽出項目の意味を個別に確認するものではありません。
既存項目の校正は無関係な話題を分ける場合の最大2項目、新規話題と概要は1項目までです。
分割で増える行数も、バッチをまたいで残りの36項目枠を共有します。
文字数枠は元の長さと復元の必要性から配り、全項目の割当て合計を全体上限の97%以内に
収めます。元の合計が既に多い場合は短縮を求めます。keepもreplaceも同じ枠で検証するため、
個別に合格した結果の合計が文字数上限を超えることを防ぎます。割当てと余裕はJSONの
qualityAudit.editorialAllocation・unitBudgetsに残します。
文字数超過の修復は項目ID・実文字数・上限を伝え、該当項目と許可した根拠だけを再送し、
戻した全体を再検証します。それ以外の校正エラーは元の入力を含めて最大1回修復します。
概要照合には校正済み本文を使い、Raw全件を再送しません。
実費は入力分割・根拠量・修復に依存します。sources.<id>.reviews.input_characters を増やすと
呼出し回数を減らせますが、抽出cacheの識別も変わるため実測で比較します。既定値は変更していません。


## 訂正・整合性確認の限界（0.35）

関連する抽出項目も誤り得るため、原文に照らして訂正・完了状態を判断します。
ユーザーが明示した変更判断と、実装に反映されたかどうかの不確実性を分けます。
概要は校正済み本文を派生元とするため、本文の誤りが残れば概要にも引き継がれ得ます。
review-notes validateは構造・期間・引用IDの検証であり、意味の整合性は保証しません。
この更新による共有プロバイダー設定・既定モデルの変更はありません。


## 根拠の重複送信を削減（0.36）

本文の表示順ではなく、共通の根拠が多い項目を同じ校正リクエストへまとめます。
選択済み原文・各項目の引用許可範囲は保持し、同一IDの抜粋は長い方を共有します。
文字数上限を守り、従来の順番でまとめた場合より回数・入力文字数が増える場合は元の構成を使います。
保存するノートの項目順は変わりません。共有根拠を他の項目が自由に引用できるようにはしません。

根拠IDは送信時だけ短いIDへ可逆変換し、応答を元のIDへ戻してから検証・cache保存します。
原文、発言者、日時、スレッド、切り詰め表示は変更しません。cache識別には対応表も含め、
同じ短縮IDが別の根拠を指す入力を混同しません。対応表はcacheに保持します。
JSONのqualityAudit.sourceTransmissionには、従来順と今回の構成の送信件数・原文文字数・
重複原文文字数を保存します。これはtoken見積もりではなく、実利用量はusageで確認します。
抽出・欠落照合のプロンプトは変更していないため、そのcacheは再利用できます。

## 出典・質問の要点・収録範囲の読み方

本文の節順と表の列数は維持します。表示名・引用ナビゲーションと制約の内訳は機械処理で作成し、追加のAI呼出しは行いません。

### 出典の表示名と引用対象

チャット名は取得元の `session_index.jsonl` のthread_nameを優先します。
索引がない、または題名が管理用文字列の場合は、実際の依頼文の先頭を100文字以内で表示します。
カタログにはtitleSource（session-index / message-fallback）を記録します。
索引の題名は表示用メタデータであり、主張を支える根拠にはしません。

`external_codex_apps_open_page`だけのイベントは、正規化・既存canonicalからのレビュー入力・Raw周辺取得で除外します。
同じイベントの後ろにある実際の依頼や、説明のために引用されたタグは保持します。Raw原本は変更しません。
月次・年次の下位レビューでも引用可能な根拠がない項目は除外し、制約として記録します。
旧JSONに残る管理用の引用は表示時に除外し、本文に根拠確認が必要と示します。主張の正しさを自動認定したり、旧JSONを黙って訂正したりしません。

本文の `[S001]` は、その項目が参照した発言の集合へリンクします。同じチャットを参照していても集合が違えばリンク先を分けます。
出典節の折りたたみ内には、引用集合と根拠IDの対応、発言者、保存された日時表記、最大160文字の抜粋、元イベントの位置を表示します。
発言を複数項目が使う場合も抜粋の行は1回にまとめます。日時の小数秒・時差は表示で丸めません。
長い複数イベント索引の位置・日時は最初と最後だけを示し、全位置と全内容はJSONに保持します。連続作業時間の意味ではありません。
見出しや本文の文字数枠は従来どおりです。出典の折りたたみには追加の文章が入るため、Markdownファイル全体のサイズは増えます。

### 質問・学びに残す要点

既存のtext欄に、問い・説明・確認された理解状態に加え、後から判断に使える説明の要点を1〜2文で残します。
「何を質問したか」「説明を受けたか」だけで終えず、回答・説明の根拠IDも引用します。
説明を受けたことを理解・実践できた証拠にはしません。説明が入力になければ未確認とし、モデルの一般知識で補いません。
抽出・統合・校正の日英プロンプトに同じ方針を含め、月次・年次にも引き継ぎます。専用の追加推論段階は増やしません。
全体の文字数・項目数の上限は維持します。プロンプトと必要な要点が増える分のtoken数は実行内容に依存します。

### 収録範囲の制約

対象範囲と出典の節で、通常ツール本文の圧縮、抜粋の切り詰め、Raw文字数・要求数の上限、正規化失敗、
不正な原文行、下位レビュー・カタログ・Raw参照の未取得、引用不能、その他を種類別の件数と影響で示します。
件数はcoverage.gapsの記録数であり、会話の欠落数・独立した失敗回数・影響した判断の数ではありません。
下位レビューから引き継いだ日付prefix付きの制約も分類し、未知の形式はその他に残します。
全診断はJSONに保持し、表示上の内訳の合計と全記録数が一致するようにします。
